**Техническое задание по проекту ИТ-Песочницы**

**«Веб-приложение для Тайного Санты»**

**Актуальность**

Многие студенты хотят организовать игру в Тайного Санту в своих группах или компаниях, но ручной процесс жеребьёвки (бумажки, шляпа) неудобен, особенно если участники живут далеко друг от друга. Создание простого и понятного веб-приложения автоматизирует этот процесс, делает его современным, удобным и безопасным. Для первокурсников этот проект станет отличным введением в основы веб-разработки, клиент-серверного взаимодействия и работы с базами данных на практическом и веселом примере.

**Цель проекта по SMART, в которой есть все критерии (1-2 предложения)**

В течение одного учебного семестра команда студентов должна спроектировать и разработать рабочее веб-приложение, которое позволяет пользователям создавать комнаты для игры в Тайного Санту, проводить автоматическую жеребьёвку и безопасно обмениваться пожеланиями к подаркам.

**Основные задачи проекта**

1. Изучить основы вёрстки (HTML, CSS) для создания простого интерфейса.
2. Изучить основы клиентского программирования (JavaScript) для интерактивности.
3. Понять принципы работы серверной части (бэкенд) и простой базы данных.
4. Реализовать безопасный алгоритм случайной жеребьёвки.
5. Обеспечить конфиденциальность данных (чтобы участники не узнали, кто их Санта).
6. Создать удобный интерфейс для регистрации, создания комнаты и просмотра результата.
7. Задеплоить приложение на хостинг, чтобы им могли пользоваться другие студенты.

**Целевая аудитория**

* Студенты и другие группы людей, желающие организовать игру в Тайного Санту онлайн.

**Требования к продукту**

Функциональные:

1. Система комнат:

* Возможность создать новую «комнату» (игру).
* Получение уникальной ссылки для приглашения участников.

1. Участники:

* Возможность присоединиться к комнате по ссылке.
* Участник вводит своё имя и email (для уведомлений).
* Участник может указать свои пожелания к подарку (текстовое поле).

1. Организатор:

* Инициатор игры (создатель комнаты) может запустить жеребьёвку, когда все участники собрались.

1. Жеребьёвка:

* Автоматический случайный алгоритм распределения участников так, чтобы никто не достал сам себя.
  + Результаты жеребьёвки сохраняются в системе.

1. Просмотр результата:

* После жеребьёвки каждый участник видит на экране только имя того, кому он должен сделать подарок (своего «подопечного»), и его пожелания.
* Организатор видит результаты жеребьёвки в случае, если поставил специальную галочку.

1. Напоминание:

* Система отправляет участникам email с именем их «подопечного» и его пожеланиями (можно реализовать условно, через вывод в консоль, или с помощью простого SMTP).

Нефункциональные:

1. Простота и понятность интерфейса: Первокурсники должны понять, как пользоваться приложением, без инструкции.
2. Конфиденциальность: Главное требование! Никто, кроме системы и организатора (если поставил галочку), не знает, кто кому выпал. Данные должны храниться безопасно.
3. Срок выполнения: Проект должен быть реализован в течение одного семестра.
4. Масштабируемость: Архитектура должна позволять в будущем легко добавлять новый функционал (например, чат, напоминания о дедлайне).
5. Документация: Весь код должен быть понятно написан и прокомментирован. Должна быть инструкция по запуску проекта локально.

**Этапы реализации проекта**

| **№** | **Этап** | **Задачи** | **Срок** |
| --- | --- | --- | --- |
| 1 | Анализ и проектирование | Изучение основ веб-разработки. Проектирование структуры БД и логики работы. | 3 недели |
| 2 | Выбор технологий | Выбор стека технологий (например, Frontend: HTML/CSS/JS, Backend: Node.js/Python + SQLite). | 1 неделя |
| 3 | Разработка интерфейса (Frontend) | Вёрстка главной страницы, страниц создания и подключения к комнате, страницы с результатом. | 3 недели |
| 4 | Разработка логики (Backend) | Написание серверной логики: создание комнат, регистрация пользователей, алгоритм жеребьёвки. | 4 недели |
| 5 | Интеграция и тестирование | Соединение фронтенда и бэкенда. Тестирование жеребьёвки на разных наборах данных. | 2 недели |
| 6 | Деплой и документация | Выкладка приложения на хостинг (например, GitHub Pages + Heroku/Glitch). Написание инструкции. | 1 неделя |
| 7 | Финальное демо | Презентация working product одногруппникам и преподавателю. | 1 неделя |

**Критерии успеха**

1. Приложение работает без критических ошибок.
2. Жеребьёвка происходит честно и случайно, участник не может вытянуть сам себя.
3. Интерфейс интуитивно понятен для целевой аудитории (студентов).
4. Код проекта выложен в открытый репозиторий (например, на GitHub).
5. Приложением можно воспользоваться по публичной ссылке.
6. Команда может объяснить, как работает каждая часть приложения.
